# Sujicraftプラグインのメンテナンス

このリポジトリを、再現可能に検証・配布できるSujicraftプラグインとして保守する。

[共通原則](../../shared/principles.md)を確認し、変更対象に応じて設計・コーディング・レビューの各スキルを併用する。

## 編集前

- `git status` と既存差分を確認し、ユーザーの未コミット変更を保護する。
- 変更対象から参照されるSKILL、共通原則、マニフェスト、テスト、文書を読む。
- リポジトリのソースとインストール済みキャッシュを区別する。キャッシュを原本として直接編集しない。
- Codex固有のマニフェスト項目、パス規則、CLI動作を変更する場合は、推測せずOpenAI公式資料の現行仕様を確認する。

## 保つべき整合性

- ルートの `plugin.json` をポータブルな識別情報の基準とする。
- `plugin.json` の `extensions.com.openai.interface` と `.codex-plugin/plugin.json` の `interface` を一致させる。
- 2つのマニフェストの `name` と `version` を一致させる。
- `.claude-plugin/plugin.json` の名前・版・説明もルートと同期する。Claude CodeとGrok Buildはこの互換設定と共通のSKILLを利用する。
- プラグイン内のパスはルート相対の `./` 形式にし、配布物の外を参照させない。
- SKILLのフォルダー名とfrontmatterの `name` を一致させ、`description` に適用対象と非対象を判別できる情報を含める。
- SKILLから共通原則や補助資料への相対参照を、ZIP展開後も解決できる状態に保つ。
- SKILLの追加・削除時は、一覧、個数検証、配布説明、変更履歴を同じ差分で更新する。
- ブランド画像や表示情報の変更時は、ルートマニフェストとCodex互換マニフェストの双方を更新する。

## 変更の進め方

### SKILLと原則

- 既存スキルと責任が重複しない、認識可能な利用目的に限定する。
- 一般論や既存の共通原則を複製せず、そのSKILLで判断が変わる指示だけを書く。
- `references/`、`scripts/`、`assets/` は、条件付きの詳細、反復処理、生成物資産として具体的な用途がある場合だけ追加する。
- 既存スキルの意味を変える場合は、想定する依頼例と非対象例への影響を確認する。

### マニフェストと配布

- 現行構成を保てる変更では、新しいマニフェスト形式や依存関係を追加しない。
- 配布内容を変更したら、互換性のある修正はパッチ、新しいSKILLや利用目的の追加はマイナーを基本としてバージョンを更新する。公開方針が別に指定されている場合は従う。
- `CHANGELOG.md` に利用者から見える変更を記録し、READMEと導入手順の版・SKILL数・生成物名を同期する。
- 配布構成の詳細と再インストール方法は [Codex導入手順](../../adapters/codex/README.md) を参照する。
- Claude Code・Grok Build対応は [アダプター一覧](../../adapters/README.md) と [対応環境の検証記録](../../validation/compatibility.md) を参照する。

## 検証

変更後は、少なくとも次を実行する。

1. 新規または変更したSKILLを利用可能なskill validatorで検証する。
2. `python scripts/package.py` でマニフェスト、SKILL、参照、配布ZIPを検証・生成する。
3. `python tests/test_package.py` で移設後の再検証、ZIP、参照欠損、Codex CLI認識を確認する。
4. `git diff --check` と最終差分で、無関係な変更、版・文書・個数の不一致、配布漏れがないことを確認する。

CLIを利用できない場合や権限制約で一部を実行できない場合は、成功扱いにせず、未検証の境界と理由を報告する。

## インストール・公開の境界

- ソースの編集依頼だけから、現在のインストール更新や外部公開の許可を推定しない。
- ユーザーが現在の環境への反映または実インストール検証も求めた場合は、検証済みソースから再インストールし、キャッシュ内の版と主要ファイルを読み取り確認する。
- 公開ディレクトリや共有ワークスペースへの提出、既存公開版の更新は、明示的な依頼がある場合だけ行う。
- 再インストール後も表示が古い場合は、ソースを再編集する前にクライアント再起動と読み込み元を確認する。

## 完了報告

- 変更したプラグイン機能とバージョン
- 同期したマニフェスト・文書・配布物
- 実行した検証と結果
- インストール反映の有無、未検証事項、残るリスク
